# Android_HA_Viewer —— 使用说明

**交付物**：`Android_HA_Viewer-v1.3.apk`（36.7 KB，versionCode 4 / versionName 1.3，minSdk 23 / targetSdk 23）

> 桌面上显示的名字是「**HA Viewer**」。
> 可直接覆盖安装 v1.0 / v1.1 / v1.2（同一签名）。

---

## 一、它做什么

把 Home Assistant 里**某一个实体**的状态变化，按时间倒序做成一条实时流水：

- **标题栏**：左边显示实体名 + 状态小字，**右上角「设置」**
- **标题栏之下只有列表**，每行 = `时间` + `变化后的值`
- **最新在最上**，新记录到达时列表**自动回到顶部**
- **WebSocket 实时推送**（默认开启），延迟降到**百毫秒级**
- 有新记录时可以**响提示音**

### 两条数据通道

| 通道 | 用途 | 延迟 |
|---|---|---|
| **WebSocket**（主） | 实时接收 `state_changed` 事件 | **~50~150 毫秒**（局域网） |
| **REST 历史接口**（辅） | 启动时的历史回溯；实时断开时的兜底；在线时每 60 秒对账一次 | 见第五节 |

标题栏会直接告诉你当前走的是哪条：

- `⚡ 实时 · 共 128 条变化` —— WebSocket 已连接
- `⏳ 连接中 · …` —— 正在建立/重连实时连接
- `⏱ 轮询 · 共 128 条变化` —— 实时不可用，已退回轮询
- `⏱ 轮询 · … · 实时失败：<原因>` —— 实时出错，具体原因会显示出来

## 二、首次配置（4 步）

### 1. 拿长期访问令牌

在**电脑浏览器**上：

1. 打开 HA → 左下角点**你的用户名** → 进「**个人资料**」
2. 切到「**安全**」标签页 → 拉到**最底部** → 「**长期访问令牌**」→「**创建令牌**」
3. 名称随便填（如 `android6`）→ 确定
4. 弹出 `eyJhbGciOiJIUzI1NiIs...` 一长串 → **立刻复制**（关掉就再也看不到）

> ✅ **普通权限用户的令牌就够了**，不需要管理员。
> 读状态、读历史、订阅 WebSocket 事件都只要求已认证用户；只有 `POST /api/states/<实体>`（直接改写状态）才限管理员，本 App 不用它。
> 但要注意：如果管理员给这个用户限制过**实体级权限**（read/control/edit），要确保这个用户对目标实体有 `read` 权限。

### 2. 装 APK

拷到手机 → 开启「未知来源」→ 点击安装。

### 3. 填配置

首次启动会**自动弹出设置页**：

| 分区 | 字段 | 填什么 |
|---|---|---|
| 连接 | 服务器地址 | `http://homeassistant.local:8123`（端口不确定就试 8123；新版 HAOS 也可能是 80） |
| 连接 | 长期访问令牌 | 上面复制的那串 |
| 连接 | 实体名 | 要监控的实体 ID，如 `sensor.xxx` |
| 连接 | 回溯小时数 | 默认 24 |
| 刷新与提示音 | 刷新间隔（秒） | 默认 2，范围 1~60。**实时在线时这个值不生效**（改为 60 秒对账） |
| 刷新与提示音 | 提示音开关 | 默认开 |
| 刷新与提示音 | 实时推送开关 | 默认开 |
| 筛选 | 筛选模式 / 关键词 | 见第四节 |

填完点「**测试连接**」——它会告诉你 HA 是否可达、令牌是否有效、实体叫什么、当前值是多少。通了再点「**保存**」。

## 三、提示音

设置页「刷新与提示音」里有一个开关（默认**开**）：

- 有**新记录**、且该记录**通过了当前黑白名单筛选**时，响一声
- 提示音用的是**系统「通知」铃声**（你在系统设置里选的那个），走通知音量，所以**手机静音时自然不会响**
- 若系统没设默认通知音，退回一声短促蜂鸣
- **同一轮请求里多条新记录只响一声**；实时推送下事件是一条条来的，所以加了 **2 秒最小间隔**节流，避免连环炸响
- **App 启动时的首次历史回溯不会响**——否则一开局就带回几十上百条历史，会响成一片

> 提示音跟着**筛选结果**走：你设白名单 `报警`，就只在报警消息进来时响；你设黑名单 `心跳`，心跳就不会吵你。

## 四、白名单 / 黑名单怎么用

设置页里有一个**开关**在两种模式间切换，下面是一份**关键词列表**（可增删多条）：

| 模式 | 行为 |
|---|---|
| **白名单** | 只显示**命中**任一关键词的记录；关键词列表为空 = 全部显示 |
| **黑名单** | **隐藏**命中任一关键词的记录；关键词列表为空 = 不过滤 |

- 匹配对象是**变化后的值文本**，**不区分大小写**，**子串匹配**
- 例：白名单填 `报警`，就只看含"报警"的变化；切到黑名单填 `心跳`，就屏蔽掉所有心跳噪声
- 切换模式时**关键词列表保留**，只是语义反转

## 五、延迟：现在是多少

### WebSocket 通道（v1.2 起的默认路径）

| # | 环节 | 耗时 |
|---|---|---|
| 1 | HA 状态机变化 → 立刻 fire `state_changed` 事件 | 毫秒级 |
| 2 | 经 WebSocket 推送到手机 | **网络往返**：局域网 10~50ms |
| 3 | 手机端 JSON 解析 + 插入列表 + 重绘 | 几毫秒 |
| | **合计** | **约 50~150 毫秒（局域网）**；公网取决于线路 |

**关键点**：这条路径**完全不经过 recorder 数据库**，所以不受 `commit_interval` 影响。这正是它能比轮询快几十倍的原因。

### 轮询通道（兜底 / 对账）

| # | 环节 | 耗时 |
|---|---|---|
| 1 | **HA recorder 落库** | **0 ~ 5 秒**（平均 2.5s） |
| 2 | 轮询等待 | 0 ~ 刷新间隔（默认 2s，平均 1s） |
| 3 | 网络 + 解析 + 渲染 | 几十毫秒 |
| | **合计** | **平均约 3.5 秒，最坏约 7 秒** |

### 为什么第 1 步存在（轮询通道）

`/api/history/period` 读的是 **recorder 的数据库**，不是内存里的实时状态机。HA 的
[`commit_interval`](https://www.home-assistant.io/integrations/recorder/#commit_interval)
默认 **5 秒**——状态变化先攒在内存里，每 5 秒批量写一次库。官方文档有一句容易误读的话：

> 代价是数据库会滞后（**activity 和 history 不会滞后，因为变化是即时流式推送给它们的**）

这句说的是 HA **自己面板**：面板额外订阅了 WebSocket 实时事件，所以看起来不延迟。
**REST 轮询享受不到那个流式推送**，所以那层延迟对轮询通道成立——这也是 v1.2 加 WebSocket 的直接原因。

### 三条通道的关系

```
启动 ──► REST 历史回溯（补上过去 24 小时）──► 列表立即可用
   └──► WebSocket 订阅 ──► 之后的新变化毫秒级到达
                            │
                            └─ 断线？自动重连（1→2→4→…→30 秒退避）
                               重连期间自动切回轮询，不漏数据
                            └─ 在线时每 60 秒仍做一次 REST 对账，
                               封住「历史回溯结束」到「实时订阅建立」之间的缝
```

**所以：实时可用时延迟百毫秒级，实时不可用时自动降级为几秒级，但列表永远不会停止更新。**

## 六、常见错误对照

| 界面提示 | 含义与排查 |
|---|---|
| `401 未授权` | 令牌写错/已失效，**或者该用户没有此实体的读取权限**。HA 对权限不足也返回 401 而非 403，所以别只怀疑令牌 |
| `404 找不到` | 实体 ID 拼错了 |
| `连接失败：...` | 地址或端口不对，或手机不在同一网段 |
| `实时失败：WebSocket 握手被拒绝：...` | WebSocket 与网页**同端口**。确认地址端口正确、反向代理放行了 `/api/websocket` 的 Upgrade |
| `实时失败：令牌被拒绝：...` | 令牌无效——但注意轮询可能是好的，说明令牌本身有效，检查是否有代理改写了请求头 |
| 连接正常但列表空白 | ① 实体在回溯窗口内确实没变化；② 该实体被 `recorder` 排除了；③ 筛选条件把记录全过滤了（看标题栏"筛选后 N 条"） |

## 七、已知限制

1. **实时连接只在 App 位于前台时保持**。切到后台/锁屏会断开（省电），回到前台自动重连并补齐空档。**没有做后台常驻 + 系统通知**。
2. **历史依赖 `recorder` 组件**（HA 默认开启）。如果被关闭或把该实体排除在外，历史回溯会返回空（但实时推送仍然工作）。
3. **HA 默认只保留 10 天历史**，回溯小时数设再大也只能拿到保留期内的数据。
4. **明文 HTTP**：Android 6 默认允许明文，所以 `http://` 能直连。但如果在**公网上**用明文传令牌，令牌等于裸奔——建议先只在局域网用；要上公网就加 SSL 或走 WireGuard/Tailscale。
5. **wss（加密 WebSocket）走系统默认证书校验**。如果是自签名证书会握手失败——当前只有 `http://` 场景经过实际验证。
6. 只监控**单个实体**；筛选模式是**二选一**（不是白名单+黑名单叠加）。

### 源码结构

| 文件 | 职责 |
|---|---|
| `WsFrame.java` | RFC 6455 帧编解码（**纯逻辑，被单测覆盖**） |
| `HaWebSocket.java` | 握手 / 鉴权 / 订阅 / 事件解析 / 心跳 |
| `HaClient.java` | REST：历史查询、连通性测试、ISO8601 时间解析（**被单测覆盖**） |
| `Prefs.java` | 配置存取 + 黑白名单判定（**被单测覆盖**） |
| `Notifier.java` | 提示音 |
| `MainActivity.java` | 列表、实时/轮询双通道调度、重连退避 |
| `SettingsActivity.java` | 设置页 |

- **v1.3**：修复同一条变化重复出现（实时推送与历史查询的时间戳精度不一致，详见 CHANGELOG）；单测增至 64 项
